# Personal project order

## Authority and intent

The user requested every project sorting mode and independent project pins, and selected personal project openings rather than background agent activity. The dispatch supplies these concrete implementation decisions: Recent, Frequent, Name and existing Manual; count only successful deliberate transitions between logical projects; preserve host/group buckets and Manual; support desktop/mobile and mixed versions. These details are coordinator decisions, not an additional user approval.

## Existing interfaces and change

- Extend `ProjectOrderBy` (`src/shared/ui-chrome-types.ts`) and `WORKSPACE_PROJECT_ORDER_CHOICES`. Workspace `sortBy` stays separate.
- Reuse `Project`/`ProjectHostSetup` projection and `getProjectGroupingForRepo`. Resolve a preference key from the actual setup: canonical `github:`/`git:` project IDs share preferences; other IDs use the proven setup host, effective execution host and project ID. Legacy repo identity requires a proven repo owner. Never resolve by label/path or lineage display placement. Raw group-owned FolderWorkspace rows retain their hierarchy and have no guessed project.
- Add optional `personalProjectOrder` to existing `PersistedUIState`: a summary/pin per logical project, monotonic revision and the latest 4,096 exact writer/sequence operation IDs. No historical backfill, click log or offline pruning. Optional data must survive unrelated old-client UI patches.
- Add capability `ui.personalProjectOrder.v1` and strict RPC `ui.recordProjectOpen` (`{projectKey, previousProjectKey, opId:{writer,seq}}`) plus `ui.setProjectPinned` (`{projectKey,pinned,opId}`). Mutations in `src/shared/personal-project-order-writes.ts` synchronously read/merge/write the existing UI store. Replays do nothing; distinct out-of-order operations still apply; distinct client writes cannot lose increments. Counts saturate at MAX_SAFE_INTEGER; owner timestamps are finite, safe and monotonic. Retry IDs and summaries survive restart.
- Reuse `navigationIntent: 'user-open'` in `worktree-activation.ts`; resolve the actual previous/destination project before changing selection and record after successful activation. Remote execution acknowledgements precede usage recording; writes go to the runtime supplying this UI, independently of the execution owner. Background activation, mounts and no-op/same-project selection record nothing. Mobile's deliberate row open records after its existing owner-routed activation acknowledges; ordinary session-route mount does not record. Home Resume carries an explicit one-shot route intent and records only after its existing activation acknowledges; the existing view client is capability-probed independently of the execution host, and replay uses the same operation ID.
- `project-section-order.ts` supplies one comparator for normal and Project Group sections. Pin is the first tier, followed by selected mode. Frequent compares count, personal Recent, visible natural label and identity. Never-opened Recent/Frequent use stable Manual then label/identity. Legacy peers retain legacy Recent semantics. `project-grouping-index.ts` preserves existing checkout grouping and indexes host-qualified setup ownership; `project-preference-identity.ts` resolves the preference key without path/name matching. Disambiguate visible labels before Name ordering.
- Carry optional summaries through the existing project catalog, window graph, main sidebar feed and mobile schema/hydration. Do not change `ORCA_SIDEBAR_INPUTS_IS_MAIN`. Use existing menus and tokens for pin/unpin and all four modes. New controls/writes require advertised capability, and selection reflects acknowledged host state. Manual drag stays within pin tiers; crossing a fixed tier boundary must be explicitly refused rather than silently persisted without visible movement.

## Acceptance

Exercise actual UI persistence/RPC, activation and row-building boundaries: quiet Alpha's personal open beats agent-active Beta; failed/background/no-op/same-project/mount do not count; restart/replay/concurrent writes; all modes and pins in normal/group/feed/mobile paths; preserved Manual; canonical Git sharing and host-local folder/SSH identity; safe old-host controls/write refusal/readback and old-client optional-field preservation. Use English hidden component fixtures or background CDP for menu/order/pin proof, with light/dark and narrow/mobile review. No provider calls or visible app launch.

## Builder decisions and self-review

Use optional metadata in the existing view store and catalog, not a new settings subsystem. Sequence dedupe is bounded; evicted ancient retries may apply again, matching existing bounded retry conventions. Do not prune unknown/offline project summaries. Self-reviewed against the dispatch and source pointers; all ordering, activation, persistence, compatibility and mobile interfaces above require implementation and verification before completion.
