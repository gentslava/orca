## Архитектурные решения

Сохранены существующие adapters, journal, account services, runtime authority и оркестрация Run/Task/Dispatch. Не создан второй агентный движок, отдельный сборщик расхода или параллельный планировщик.

Claude продолжает запускать оригинальный Claude Code через официальный SDK с явно разрешённым executable и существующими источниками настроек. Вызовы Anthropic через собственный inference loop с подписочными credentials не добавлялись. Это проверка реализации, а не гарантия решений провайдера по аккаунтам.

Нативный Gemini использует оригинальный Gemini CLI 0.65.0 через ACP: новый чат, поток текста и доступных reasoning-событий, tools, изображения, разрешения, отмена и модель из live-каталога сессии. Версия и initialize/signed-out response проверены на оригинальном npm executable в пустом HOME через настоящий Orca ACP connector без платного prompt. Native reopen/adoption отключены до появления в оригинальном протоколе безопасной границы replay; сохранённый журнал можно читать. Worker `--model` для Gemini остаётся неподдерживаемым, live-выбор модели в открытой сессии работает. Effort/Fast не объявляются без данных провайдера.

`usage.history.v1`, `orchestration.session-children.v1` и `orchestration.worker-role-routing.v1` объявляются существующим механизмом capabilities. Запросы уходят к выбранному владельцу; старый, отключённый или неизвестный сервер не заменяется локальными данными. Неизвестный результат запуска не запускает повторную пишущую задачу.

История субагента читается через существующие history/subscribe без acquire, attach, send или takeover. Сведения о провайдере/сервере служат отображению и не дают полномочий на чтение другой ленты. Ссылки дочернего проекта не открываются в каталоге родителя; скрытый родитель не получает печать или вставку из дочернего viewport.

## Что означают цифры расхода

Подписочная квота принадлежит аккаунту и не становится квотой проекта при фильтрации истории. Оценка по тарифам API не равна сумме списания за подписку. Неизвестная цена не считается нулём; частичный расчёт помечен. Кешированный ввод и reasoning не прибавляются повторно к уже включающим их категориям.

Для Claude, Codex и OpenCode используются существующие выделенные источники аккаунтов. Скопированные события сохраняют дедупликацию и доказанную принадлежность; противоречащие копии, старые общие логи, потерянный provenance и источники через symlink/hardlink не назначаются текущему аккаунту. Для Muse и старых общих логов принадлежность может остаться неизвестной. Переключение аккаунта не переписывает историю.

## Ограничения, которые остаются видимыми

- Полная лента доступна для подтверждённых structured-сессий на владельце родительского runtime, в том числе при подключении к нему удалённо. PTY и worker на другом runtime могут дать только метаданные и сохранённый результат; это явно показано.
- Параметры будущего сообщения не меняют скрытое состояние уже запущенной модели. Переключение провайдера сохраняет отдельную provider-сессию; общий контекст передаётся через задачу и результат.
- Роли задают явную политику выбора. Автоматический балансировщик по остаткам подписок, бюджету и сбоям не реализован. Лимиты параллельности и безопасные повторные попытки продолжают определяться существующей оркестрацией.
- Standalone React Native mobile получил компактные действия и доступные busy-параметры на поддерживающем сервере; полный русский, собственный экран дочерней ленты и перестановка очереди там не объявляются готовыми. Общий web renderer использует новый интерфейс.
- Реальные авторизованные платные ответы провайдеров не запускались. Протокольные проверки и установка оригинального executable проверяются отдельно от платного end-to-end сценария.
- Предыдущий полный E2E TypeScript project имел 252 диагностических сообщения вне нового русского spec; новый spec имел ноль. Это не зелёный полный E2E typecheck. Прикладные Node/Web/CLI/mobile проверки перечисляются отдельно.
- Docker проверен на Linux arm64 через Docker Desktop. Linux amd64, Windows/Linux GUI, настоящий WSL и пользовательский удалённый сервер не проходили живой прогон.

## Docker

Инструкция: [config/docker/orcad/README.md](../../config/docker/orcad/README.md). Конфигурация не публикует образ в registry и не разворачивает сервер пользователя. Старый проверенный контейнер пересобирается из окончательного дерева перед фиксацией версии артефакта.

Настройка создаёт отдельный env-файл и отказывается затирать существующий. Для своего развёртывания сохраняются адреса, версии оригинальных CLI и все три тома. Pairing выполняется в штатном разделе Remote Orca Servers. Секреты и provider HOME не встраиваются в образ.

Приёмочная fixture использует отдельный Compose project, пустые тома и loopback-порт: pairing, повторное соединение, restart, replacement, рабочий файл, журнал, machine-id, sealed несекретный placeholder, оригинальный CLI, история Usage через аутентифицированный RPC и отрицательная проверка здоровья daemon. На пользовательский сервер ничего не устанавливается.
